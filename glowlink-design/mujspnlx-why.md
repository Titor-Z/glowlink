# 萤光 GlowLink 产品需求文档（PRD）

**版本**：v1.0 (MVP 规划期)
**文档状态**：定稿，作为开发基石
**产品性质**：闭源、本地优先、去中心化的跨平台近场文件传输网络
**核心标语**：萤萤之光，可照旷野。
**产品定位**：打破 Android、iOS、Windows、macOS、Linux 之间的生态壁垒，提供无感直连、极速传输、绝对隐私的局域网/无网直连文件互传体验。

---

## 一、 产品背景与核心痛点

### 1.1 市场现状
*   **苹果 AirDrop**：体验极佳，但**封闭于 Apple 生态**，无法与 Android/Windows 通信。
*   **华为星闪（NearLink）**：速度快、时延低，但**依赖专用硬件与鸿蒙生态**，第三方设备无法接入，且无法跨生态。
*   **LocalSend 等开源方案**：虽然跨平台，但**依赖公共路由器**，在无网环境下无法自组网；且开源代码暴露了传输协议细节，**易受恶意伪造包攻击**，安全性存疑。
*   **传统方案（蓝牙/HTTP服务器/热点）**：蓝牙传输速度极慢（无法满足大文件）；手动开热点、输 IP、建 HTTP 服务器等操作极度反人类，效率低下。

### 1.2 核心痛点
用户需要一个**无需云端、无需配置、点对点直连、跨全平台**的工具。无论身处何地（家里、公司、户外无网环境），只要设备靠近，就能像“星闪”一样快速、安全地传输文件。

---

## 二、 产品愿景与核心理念

1.  **去中心化（Decentralized）**：无中心服务器，无云端介入。每一台设备都是平等的节点，自组网、自发现。
2.  **无感自组网（Self-organizing）**：软件常驻后台，自动感知周边设备。用户无需手动连接网络或输入 IP。
3.  **跨平台破壁（Cross-platform）**：全面覆盖 Windows、macOS、Linux、Android 四大主流系统。
4.  **极简交互（Minimalist）**：抛弃复杂列表，采用 320x500 小窗口的**节点图（Node Graph）** 交互。本机为中心，周围为发现的设备，点击即连。
5.  **闭源私有协议（Closed-source & Secure）**：代码与协议细节完全闭源，防止恶意嗅探与攻击。无遥测、无注册、无数据收集。
6.  **极致性能（Performance）**：基于 Rust 核心，无 GC、内存可控，利用生产者-消费者模型与环形缓冲池实现极速、稳定的文件流传输。

---

## 三、 用户画像与核心场景

*   **开发者/设计师（跨平台办公）**：拥有 Mac 和 Windows 双设备，需要频繁在两端同步图标、代码片段、设计稿，不想依赖云盘或 IM 软件。
*   **户外工作者/差旅人士**：在没有公共 WiFi 的环境下（如高铁、户外），需要将手机照片快速传给同行人的平板或电脑。
*   **隐私敏感用户**：拒绝使用微信、网盘等中转工具传输敏感文件，要求数据只在设备间点对点传输，不留痕迹。

## 四、 详细功能需求

### 4.1 设备发现（Discovery）
*   **同局域网模式**：通过 UDP 广播 (255.255.255.255:8888) 自动发现同网段内的在线设备。
*   **无网离线模式（进阶）**：调用底层 API（Android/Windows 优先），通过 Wi-Fi Direct 或软件自建热点能力，自动组网。Apple 设备降级为“连接安卓/Windows 开启的热点”。
*   **降级兜底**：在 WiFi 受限或仅传小文本时，使用蓝牙 BLE 进行设备发现或极低速传输。
*   **设备列表**：维护本地设备列表，超时未广播的设备自动下线。

### 4.2 数据传输（Transfer）
*   **通道建立**：基于原生 TCP Socket，不依赖 HTTP。
*   **自定义私有协议**：
    *   `[4字节] 文件名长度` + `[N字节] 文件名` + `[8字节] 文件大小` + `[M字节] 文件内容`（分块发送）。
    *   自定义校验逻辑，防止数据包被篡改或伪造。
*   **内存与流控**：
    *   采用 Rust 编写核心，杜绝 GC 卡顿。
    *   实现生产者-消费者模型 + **环形缓冲池（Ring Buffer）**。
    *   实现**背压控制（Backpressure）**：发送端读取磁盘速度与接收端写入磁盘速度自动匹配，防止内存溢出。
    *   引入“交叉淡入淡出”思路处理缓冲块拼接，确保文件流绝对完整，不丢包、不乱序。

### 4.3 系统级体验（System Integration）
*   **常驻后台**：
    *   Windows：托盘图标、开机自启（注册表或服务）。
    *   macOS：菜单栏图标、LaunchAgent 登录自启。
    *   Android：前台服务（带轻量通知，防系统杀后台）。
*   **极简 UI**：
    *   320x500 无边框小窗口。
    *   动态节点图：本机为中心节点，周围围绕已发现设备，点击设备即可发送文件。
*   **系统通知**：接收文件时，调用原生 Toast 通知（Windows Toast / macOS Notification Center / Android Notification），不走应用内弹窗。
*   **分享菜单接入（Android）**：注册 `ACTION_SEND`，用户在相册或文件管理器选中文件点击“分享”，选择“萤光”后，直接弹出节点图界面发送。

### 4.4 安全与隐私（Security & Privacy）
*   **纯本地传输**：严禁任何外网请求，无云端、无日志、无遥测。
*   **私有加密协议**：闭源意味着自定义的二进制协议无法被轻易逆向。支持端到端加密（TLS 1.3 或 Noise 协议），首次配对需确认 6 位数字配对码，后续记住设备指纹自动信任。
*   **接收确认**：任何设备向本机发送文件前，本机必须弹出系统级确认（确认接收 / 拒绝），防止恶意骚扰。

## 五、 技术架构选型

坚持“核心统一，UI 原生”的原则，保证各平台性能最大化。

```text
┌─────────────────────────────────────────────────────────┐
│                    Rust 核心库 (glowlink-core)           │
│  [Discovery]  UDP 广播 + Wi-Fi Direct 状态机              │
│  [Protocol]   自定义二进制编解码 + 校验                   │
│  [Transfer]   TCP 流式传输 + 环形缓冲池 + 背压控制          │
│  [Crypto]     端到端加密 (Noise/TLS) + 设备指纹信任机制    │
└─────────────────────────────────────────────────────────┘
           │                │                │
    ┌──────┴──────┐  ┌──────┴──────┐  ┌──────┴──────┐
    │   Windows   │  │    macOS    │  │   Android   │
    │    GPUI     │  │    GPUI     │  │  Compose UI │
    │ 托盘/服务   │  │ LaunchAgent │  │ 前台服务/分享│
    └─────────────┘  └─────────────┘  └─────────────┘
```

*   **核心层（Rust）**：编译为动态库（`.dll` / `.dylib` / `.so`），供各平台调用。性能极致，内存可控。
*   **桌面端 UI（GPUI）**：抛弃 WebView 方案（如 Tauri），使用 Zed 编辑器底层的 GPUI 框架，实现真正轻量、启动快、内存占用低的小窗口交互。
*   **移动端 UI（Jetpack Compose）**：底层通过 JNI 调用 Rust 核心，UI 层纯原生。
*   **降级策略**：Apple 生态（macOS/iOS）无法调用底层 Wi-Fi Direct API，此时引导用户开启系统热点（由 Android/Windows 充当路由器），或连接同一路由器。

## 七、 里程碑规划（MVP 路线图）

### Phase 1：Rust CLI 概念验证（当前阶段）
*   实现 UDP 广播发现（`glowlink list` 能扫出设备）。
*   实现 TCP 极简私有协议传输（`glowlink send [设备] [文件]`）。
*   实现环形缓冲池与背压控制。
*   在 Windows 与 macOS 上跑通，解决跨平台传图标/代码的需求。

### Phase 2：桌面端 GPUI 界面
*   实现 320x500 无边框、圆角小窗。
*   实现托盘常驻，点击弹出节点图，拖拽文件发送。
*   实现系统原生通知接入。

### Phase 3：Android App 与分享菜单
*   Rust 交叉编译为 Android 库（JNI）。
*   实现 Compose 节点图界面。
*   注册 `ACTION_SEND`，实现“选中图片 -> 分享 -> 选中萤光 -> 秒传”。

### Phase 4：底层自组网与安全增强
*   接入 Wi-Fi Direct API，摆脱对公共路由器的依赖。
*   适配蓝牙 BLE 降级协议。
*   引入基于 Noise 协议或 TLS 的端到端加密，增加首次配对信任机制。
*   尝试跨公网穿透（WebRTC 辅助），实现异地内网设备直连（可选扩展）。

## 八、 闭源产品的信任补偿机制

作为闭源产品，用户最大的顾虑是：“我凭什么信任你？”
必须通过以下机制弥补闭源带来的信任缺失：

1.  **零信任隐私承诺**：官网明确声明“无云端、无注册、无数据收集、无遥测”。
2.  **本地隔离自证**：提供网络诊断工具，用户可自行抓包验证，证明软件只发送 UDP 广播和 TCP 点对点数据，无任何外网连接。
3.  **安全白皮书**：公开加密方式（如 Noise 协议、TLS 1.3）、哈希校验机制，让安全社区审计背书。
4.  **代码签名**：购买 Apple Developer 和 Windows 代码签名证书，保证系统不拦截，提升商业级信任感。
